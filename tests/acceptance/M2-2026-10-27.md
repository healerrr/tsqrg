# M2 真实联机验收记录

日期：2026-10-27（Asia/Shanghai）。数据库为真实 PostgreSQL 17.10，API `http://127.0.0.1:3000`、Web `http://127.0.0.1:5173`，规则 1.0.0。Windows 10.0.19045 x64、Node.js 24.12.0、pnpm 9.15.5。浏览器为 Edge 131.0.2903.86、Chrome 155.0.8059.86。本轮浏览器仍使用此前配置的 SwiftShader；后续默认已改回本机硬件 WebGL。

## 双会话与控制权

实际命令：

```powershell
$env:AQUARIUM_E2E_REPORT='artifacts/m2/e2e-results.json'
pnpm exec playwright test -c tests/e2e/playwright.config.ts --grep M2 --output artifacts/m2/e2e
```

最终结果：**4 项通过，0 项失败，用时 1.5 分钟**。Edge、Chrome 各执行：

- 两个独立 BrowserContext 分别用 HttpOnly Cookie 建立游客并创建不同角色，通过正常 Web 页面连接真实 Socket.IO 主缸。A 的真实键盘输入使服务器位置前进超过 60 世界单位，B 的实际渲染实体观察到对应移动。没有使用同一页面的假鱼替代另一会话。
- 刷新后账号、鱼 ID 与余额保留，重复游客恢复不重新发新手奖励。
- 同账号第二连接最初只能观察；主动接管后旧连接降为观察，sceneEpoch 变化。旧连接输入、旧 epoch 输入、重放 inputSeq 均不能移动角色，新的有效连接与单调序号可以操控。

JSON 为 `artifacts/m2/e2e-results.json`，双视角截图位于 `artifacts/m2/e2e/` 对应测试目录。输入方向、实际服务器 ack 和坐标采样包含于报告附件，未包含 Cookie。联机测试禁用 Playwright trace。

## 异常重启与持久保存

实际命令：

```powershell
$env:AQUARIUM_RESTART_MARKER='artifacts/m2/restart-trigger-4.json'
pnpm exec tsx tests/acceptance/restart-check.ts
```

测试在浏览器内存持有 Cookie，写入不含凭据的触发文件；预先启动的 PowerShell watcher 对旧游戏 PID 执行 `Stop-Process -Force`，停机 3 秒后重新启动同一个真实数据库上的服务器。测试实际观察停机及重新就绪，且必须验证实例 UUID 改变。

**实际通过**：实例由 `f91f839b-1c60-4ff2-b279-d7e764d85a08` 变为 `67f80c84-2c44-49e7-9b3b-3184370767f1`。账号、鱼 ID、经验、外观、可争夺余额和冻结额度全部与重启前一致。Cookie 没有写入磁盘。证据为 `artifacts/m2/server-restart.json`、`artifacts/m2/after-server-restart.png`。

此前协调测试曾因等待超时未通过；另一次基于短暂 health 超时的旧测试不足以证明实际进程重启，其无效产物已删除。最终证据增加实例 UUID 断言并使用文件触发，不能由一次慢请求伪造成功。

## 修复和边界

曾定位到 Windows 在软件 WebGL 高负载下新建 PostgreSQL 连接超过 5 秒的临时 500，已调整池保活、连接等待和启动预热，最终联机四测未再出现。NET01 测试按服务器实际位移等待，避免把无头软件渲染速度当作服务器网络正确性的假设。

150ms 延迟/丢包恢复、30 真实连接性能、长期内存以及全部最终兼容验收仍留到后续阶段；本记录不把它们列为通过。正式比赛、商城、组织也不属于本轮 M2 验收结果。
